ΑΝΑΛΥΤΙΚΗ ΠΑΡΟΥΣΙΑΣΗ — EducationalMedicalCenter.java

Δημιουργία για προφορική ή γραπτή παρουσίαση. Συνδέεται με το σύντομο οδηγό 
slides/demo στο αρχείο PRESENTATION_EL.txt.

--------------------------------------------------------------------------------
1. Τι είναι η εφαρμογή
--------------------------------------------------------------------------------
Μία κονσολική (CLI) εφαρμογή Java που προσομοιώνει διαγνωστικό ιατρικό κέντρο.
Διαχειρίζεται τέσσερις οντότητες και τις σχέσεις τους:
  • Doctor      — γιατρός με ειδικότητα και χρόνια προϋπηρεσίας
  • Patient     — ασθενής με στοιχεία επικοινωνίας
  • Exam        — εξέταση (τρεις τύποι μέσω κληρονομικότητας)
  • Appointment — ραντεβού: συνδέει ασθενή με εξέταση, ημερομηνία, γρήγορα αποτελέσματα

Η μνήμη των δεδομένων είναι στατικές λίστες μέσα στην κλάση· στην έξοδο τα δεδομένα 
γράφονται σε αρχεία κειμένου CSV. Στην εκκίνηση γίνεται φόρτωση ή αρχικοποίηση demo.

2. Διάγραμμα ροής εκτέλεσης
--------------------------------------------------------------------------------
  JVM καλεί main
       |
       v
  loadData()  ---> αν λείπει simple_doctors.txt --> createStartingData()
       |
       v
  +---------------------------+
  | while(running)            |
  |   printMainMenu           |
  |   choice = readInt        |
  |   ανάλογα με choice -> μέθοδοι CRUD / λίστες / στατιστικά |
  |   choice==0 -> running=false |
  +---------------------------+
       |
       v
  saveData() --> UTF-8 στα simple_*.txt
  "Data saved."

--------------------------------------------------------------------------------
4. Περίληψη κώδικα ανά περιοχή γραμμών (λογικά μπλοκ)
--------------------------------------------------------------------------------

Γραμμές 1-10 — Εισαγωγές (imports)
  IOException για έλεγχο σφαλμάτων αρχείων.
  StandardCharsets.UTF_8 για σταθερή κωδικοποίηση ελληνικών/latin στο δίσκο.
  java.nio.file.* για Files.exists, readAllLines, write (API NIO.2).
  ArrayList, List, Comparator για συλλογές και ταξινόμηση.
  Scanner για είσοδο από System.in γραμμή-γραμμή.

Γραμμές 11-21 — Κλάση και καθολική κατάσταση
  Ονόματα τεσσάρων αρχείων ως σταθερές (final String).
  Τέσσερις στατικές ArrayList κρατούν όλα τα runtime δεδομένα.
  Ένα στατικό Scanner: ένα σημείο εισόδου για όλη την εφαρμογή.

Γραμμές 23-58 — main
  Φόρτωση, βρόχος μενού, dispatch με αλληλουχία if/else if (απλό αλλά διαφανές για διδασκαλία).
  Μετά το βρόχο υποχρεωτική αποθήκευση ώστε οι αλλαγές να μη χάνονται.

Γραμμές 60-73 — printMainMenu
  Εκτύπωση τίτλου και επιλογών · κενή γραμμή πριν για αναγνωσιμότητα.

Γραμμές 75-169 — Προσθήκες
  addDoctor / addPatient: αυτόματο id με next*Id(), μετά δημιουργία αντικειμένου και add στη λίστα.
  addExam: προαπαιτεί γιατρούς· επαλήθευση doctorId· επιλογή τύπου 1/2/3 και δημιουργία της αντίστοιχης υποκλάσης Exam.
  addAppointment: προαπαιτεί ασθενείς και εξετάσεις· επαλήθευση ids· έλεγχος πλήρωσης ημερήσιων θέσεων με countAppointments και maxSlotsPerDay· readYesNo για fast results.

Γραμμές 171-208 — Λίστες
  listDoctors / listPatients: απλή επανάληψη for-each + toString().
  listExams: ταξινόμηση λίστας κατά όνομα με Comparator και toLowerCase ώστε η σειρά να είναι αλφαβητική χωρίς ευαισθησία σε κεφαλαία.
  listAppointments: εύρεση patient/exam από ids· αν λείπουν εμφανίζεται "?"· το κόστος υπολογίζεται με exam.getCost(fastResults) — δυναμική δέσμευση (πολυμορφισμός).

Γραμμές 210-237 — printStatistics
  Δύο nested loops: πρώτο ανά ασθενή (άθροισμα κόστους ραντεβού του)· δεύτερο ανά εξέταση (άθροισμα κόστους για όλα τα ραντεβού σε αυτή την εξέταση).

Γραμμές 239-274 — find* και countAppointments
  Γραμική αναζήτηση O(n) σε κάθε λίστα — επαρκές για εκπαιδευτικό μέγεθος δεδομένων.
  countAppointments: ισότητα και examId και ημερομηνίας ως ακριβής συμβολοσειρά.

Γραμμές 276-314 — next*Id
  Εύρεση μέγιστου υπάρχοντος id στη λίστα και επιστροφή max+1.
  Σημείωση για παρουσίαση: αν διαγραφεί εγγραφή, ο αριθμός μπορεί να επαναχρησιμοποιηθεί αργότερα· δεν είναι UUID.

Γραμμές 316-347 — Είσοδος
  readText: trim για κενά στις άκρες.
  readInt/readDouble: επανάληψη μέχρι επιτυχές parse — αντοχή σε λάθος μορφή.
  readYesNo: μόνο "y" ή "yes" θεωρούνται true μετά από lower case.

Γραμμές 349-397 — loadData
  Αν δεν υπάρχει το αρχείο γιατρών -> demo δεδομένα και τέλος φόρτωσης.
  Διαφορετικά: ανάγνωση γραμμών, split(",", -1) ώστε κενά πεδία στο τέλος γραμμής να μην χάνονται.
  Εξετάσεις: πρώτη στήλη discrimination tag (IMAGING/MICRO/SPEC).
  Σε γενική Exception: καθαρισμός λιστών και επαναφορά demo — αποφυγή κρασαρίσματος από χαλασμένο CSV.

Γραμμές 399-429 — saveData
  Δόμηση γραμμών CSV ανά οντότητα· για Exam χρησιμοποιείται fileLine() για σωστό prefix τύπου.
  IOException καταγράφεται με μήνυμα.

Γραμμές 431-449 — readLines / writeLines / toInt / toDouble
  Επικάλυψη πάνω σε NIO· αν λείπει αρχείο ανάγνωσης επιστρέφεται κενή λίστα.
  Parsing με trim.

Γραμμές 451-465 — createStartingData
  Σταθερό σετ δειγματικών εγγραφών για άμεση δοκιμή χωρίς χειροκίνητη εισαγωγή.

Γραμμές 467-627 — Εσωτερικές static κλάσεις
  Doctor, Patient: POJO με πεδία και toString().
  Exam abstract: κοινά πεδία + abstract getCost(boolean) + abstract fileLine().
  ImagingExam / MicrobiologicalExam / SpecializedExam: διαφορετικοί συντελεστές για fast (x1.10, x1.20, x1.30).
  Appointment: συσχετίζει ids και ημερομηνία ως String και boolean fastResults.

5. Μορφή αρχείων CSV (για διαφάνεια ή πίνακα στον πίνακα)
--------------------------------------------------------------------------------

simple_doctors.txt — κάθε γραμμή:
  id,name,phone,specialty,years

simple_patients.txt:
  id,name,phone,email

simple_exams.txt — πρώτη στήλη κωδικός τύπου:
  TAG,id,name,maxSlotsPerDay,baseCost,doctorId,extraField
  TAG ∈ { IMAGING, MICRO, SPEC }
  extraField = machineType | sampleType | exam specialty text

simple_appointments.txt:
  id,patientId,examId,dateString,fastResultsBoolean


--------------------------------------------------------------------------------
6. Ιεραρχία Exam και γιατί είναι διδακτική
--------------------------------------------------------------------------------
Η abstract μέθοδος getCost(boolean fastResults) επιτρέπει στο υπόλοιπο πρόγραμμα να καλεί
το ίδιο όνομα μεθόδου σε οποιαδήποτε υποκλάση χωρίς instanceof/if ανά τύπο στην listAppointments
και στα στατιστικά — κλασικός πολυμορφισμός Java.

Πίνακας συντελεστών γρήγορων αποτελεσμάτων (επί του baseCost):
  ImagingExam          -> +10%  (x 1.10)
  MicrobiologicalExam -> +20%  (x 1.20)
  SpecializedExam      -> +30%  (x 1.30)


--------------------------------------------------------------------------------
7. Επιχειρησιακοί κανόνες που πρέπει να ειπωθούν στην παρουσίαση
--------------------------------------------------------------------------------
  • Κανένα ραντεβού χωρίς τουλάχιστον έναν ασθενή και μία εξέταση.
  • Καμία νέα εξέταση χωρίς τουλάχιστον έναν γιατρό και έγκυρο doctorId.
  • Περιορισμός ραντεβού ανά ημέρα ανά εξέταση: πλήθος ραντεβού με ίδιο examId και ίδια date < maxSlotsPerDay.
  • Η ημερομηνία είναι αποθηκευμένη ως string — η εφαρμογή ΔΕΝ επικυρώνει ημερολογιακή ορθότητα ούτε μορφή πέρα από ότι δίνει ο χρήστης.


--------------------------------------------------------------------------------
8. Περιορισμοί / θέματα για συζήτηση (bonus στην παρουσίαση)
--------------------------------------------------------------------------------
  • Όλα τα πεδία static — δεν υπάρχει dependency injection· δύσκολο το παράλληλο testing.
  • Γραμικές αναζητήσεις και επανειλημμένα scans των λιστών στα στατιστικά — O(n*m).
  • Τα CSV δεν escape-άρουν κόμμα μέσα σε ονόματα — αν το όνομα έχει κόμμα θα σπάσει το parse.
  • Κλείσιμο Scanner(System.in) συνήθως αφήνεται στο JVM στην έξοδο — για μεγάλα projects θα χρειαζόταν προσεκτικό resource management.
