Εξηγηση codebase diagnostic_medicalcenter-main

Αυτη η εφαρμογη ειναι ενα απλο Java console application για ενα διαγνωστικο ιατρικο κεντρο. Δεν χρησιμοποιει Maven, Gradle ή packages. Ολα τα source files βρισκονται απευθειας στον φακελο:

/home/krimits/diagnostic_medicalcenter-main

Γενικη εικονα

Η εφαρμογη διαχειριζεται τεσσερις βασικες οντοτητες:

- Γιατρους
- Ασθενεις
- Εξετασεις
- Ραντεβου

Το σημειο εκκινησης ειναι το Main.java. Κατα την εκκινηση ελεγχει τα αρχεια δεδομενων, φορτωνει υπαρχοντα δεδομενα αν υπαρχουν ολα τα απαιτουμενα αρχεια, δημιουργει αρχικα δοκιμαστικα δεδομενα αν δεν υπαρχει κανενα αρχειο, ή τερματιζει αν υπαρχουν μονο μερικα απο τα αρχεια. Στη συνεχεια εμφανιζει το βασικο μενου, απο το οποιο ο χρηστης μπορει να μεταβει στα υπομενου για γιατρους, ασθενεις, εξετασεις, ραντεβου και στατιστικα.

Κυρια ροη εκτελεσης

Το Main.java δημιουργει τα εξης αντικειμενα:

MedicalCenterStore store = new CsvMedicalCenterStore(new DataStore());
MedicalCenter center = new MedicalCenter();

Στη συνεχεια:

1. Η μεθοδος store.status() ελεγχει αν υπαρχουν τα αρχεια doctors.txt, patients.txt, exams.txt και appointments.txt.
2. Αν λειπουν ολα τα αρχεια, η center.seedInitialData() δημιουργει αρχικες εγγραφες.
3. Αν υπαρχουν ολα τα αρχεια, η store.loadSnapshot() τα φορτωνει.
4. Ο χρηστης δουλευει μεσα απο τα console menus.
5. Στην εξοδο, η store.saveSnapshot(center.toSnapshot()) αποθηκευει ξανα ολα τα δεδομενα στα text files.

Το βασικο μενου στο Main.java δινει επιλογες 1-5 και καλει τα αντιστοιχα υπομενου για γιατρους, ασθενεις, εξετασεις, ραντεβου και στατιστικα.

Domain layer

Το κεντρικο business object ειναι το MedicalCenter.java. Αυτη η κλαση κρατα στη μνημη τεσσερις λιστες:

- doctors
- patients
- exams
- appointments

Παρεχει μεθοδους αναζητησης οπως:

- findDoctorById
- findPatientById
- findExamById
- findAppointmentById

Παρεχει επισης βοηθητικες μεθοδους για queries, οπως:

- εξετασεις ταξινομημενες με βαση το ονομα
- εξετασεις που επιβλεπει ενας γιατρος
- ραντεβου ενος ασθενη
- ραντεβου μιας εξετασης
- ραντεβου ενος γιατρου
- ραντεβου σε συγκεκριμενη ημερομηνια

Οι βασικοι επιχειρησιακοι κανονες εφαρμοζονται επισης στο MedicalCenter.java. Για παραδειγμα, κατα την προσθηκη νεου ραντεβου, η εφαρμογη ελεγχει οτι το appointment ID δεν υπαρχει ηδη και οτι η επιλεγμενη εξεταση εχει διαθεσιμα slots για τη συγκεκριμενη ημερομηνια.

Model classes

Οι απλες entity classes ειναι:

- Doctor.java: περιεχει doctor ID, ονομα, τηλεφωνο, ειδικοτητα και χρονια εμπειριας.
- Patient.java: περιεχει patient ID, ονομα, τηλεφωνο και email.
- Appointment.java: περιεχει appointment ID, patient ID, exam ID, επιλογη fast results και ημερομηνια.

Οι εξετασεις χρησιμοποιουν κληρονομικοτητα. Η Exam.java ειναι abstract class και οριζει τα κοινα πεδια:

- exam ID
- κατηγορια
- ονομα εξετασης
- μεγιστο αριθμο ραντεβου ανα ημερα
- βασικο κοστος
- ID του γιατρου που επιβλεπει την εξεταση

Η Exam απαιτει απο τις subclasses να υλοποιησουν τη μεθοδο getCost(boolean fastResults).

Οι τρεις subclasses ειναι:

- ImagingExamination: τυπος μηχανηματος και 10% προσαυξηση για fast results.
- MicrobiologicalExamination: τυπος δειγματος και 20% προσαυξηση.
- SpecializedExamination: ειδικοτητα εξετασης και 30% προσαυξηση.

Αρα, αν ενα ραντεβου ζητα fast results, το τελικο εσοδο υπολογιζεται απο την πραγματικη subclass της εξετασης.

Persistence

Η αποθηκευση χωριζεται σε δυο επιπεδα:

- DataStore.java: κανει τις απλες αναγνωσεις και εγγραφες αρχειων.
- CsvMedicalCenterStore.java: μετατρεπει τις γραμμες κειμενου σε Java objects και τα Java objects ξανα σε γραμμες κειμενου.

Τα αρχεια δεδομενων ειναι:

- doctors.txt
- patients.txt
- exams.txt
- appointments.txt

Οι γραμμες των εξετασεων περιλαμβανουν ενα type tag, οπως IMAGING, MICRO ή SPEC, ωστε ο loader να γνωριζει ποια subclass πρεπει να δημιουργησει.

Input validation

Το InputHelper.java συγκεντρωνει τον ελεγχο εισοδου απο το console. Χειριζεται:

- επιλογες μενου μεσα σε αριθμητικο ευρος
- μη κενες τιμες κειμενου
- θετικους ακεραιους
- μη αρνητικους δεκαδικους
- yes/no prompts
- validation ημερομηνιας σε μορφη dd:MM:yyyy, ενω δεχεται και dd/MM/yyyy

Αυτο κρατα το Main.java πιο καθαρο, επειδη ο κωδικας των menus δεν χρειαζεται να κανει παντου parsing της ακατεργαστης εισοδου απο το Scanner.

Στατιστικα

Τα στατιστικα υλοποιουνται στο Main.java. Η εφαρμογη μπορει να υπολογισει εσοδα:

- ανα ασθενη
- ανα εξεταση
- ανα κατηγορια εξετασης

Το εσοδο υπολογιζεται μεσω της MedicalCenter.revenueForAppointment, η οποια βρισκει την εξεταση και καλει τη μεθοδο Exam.getCost(fastResults).
